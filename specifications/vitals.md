## Authored display contract

The third panel is a full-width row below Problem List and Allergies in a vertically scrollable Cover Sheet. Selection, explicit focus commands and lower actions reveal their own row. Header, navigation and status stay outside the workspace scroll. This is a bounded layout policy, not a site's original configurable grid.

The four recovered headings are retained. Each invented row has exact synthetic patient ID, a per-panel unique item ID, label and `VitalDisplay` strings for value (including its authored unit), timestamp and qualifiers. Values are never parsed, normalized, converted, sorted by severity, trended or interpreted. All nonempty patients share the same invented display strings intentionally; ownership is carried by explicit IDs. `SYNTH-002` has an empty Vitals list. An empty list says only that no synthetic entries exist, never a clinical finding.

Selection only highlights. Enter, Space, View item detail and authored double-click open the common mock detail pane. Its text includes patient and item identities, matching fixture strings, and read-only scope. This pane is an intentional departure from the recovered `OnShowDetail` dispatch, chosen to keep the prototype within approved viewing scope. The conversion line is omitted entirely. No graph, entry/edit, DLL launch, conversion, printing or signing action exists.

The existing generation/patient/panel/item guards also apply to Vitals. Closing invalidates pending work and returns focus to its own table while retaining selection. Patient selection clears all three selections and detail text immediately; cancellation preserves the committed chart. A new chart commits only if the Cover Sheet owner and every row match, IDs/labels are nonempty, IDs are unique per panel, and Vitals display data is attached only to Vitals. Stale/duplicate success and failure replies cannot reopen detail or overwrite current text. Unavailable detail is explicit and retry is deliberate; it is distinct from an empty panel.

## Acceptance

Eight [Vitals core cases](../crates/chart-core/tests/vitals.rs) extend the existing 70 tests. Immediate desktop callbacks cover selection/activation, double-click, exact units/timestamps/Unicode, empty rows, clearing and error/retry. The real-timer journey adds Vitals close/race, close/selection retention, error/retry, late failure after tab change, selector cancellation, same item ID under a new owner, empty list and final review state; see [integrated acceptance](integrated-chart.md).

Native keyboard/layout observations and UIA snapshots are recorded separately in [Milestone 8](../docs/milestone-8.md). A separate affected-controls user listening checklist is required; historical Milestone 7 speech results do not establish a new Vitals pass. Focus probes and callback invocation are not physical key input or spoken-output evidence. No full accessibility, original-client parity, clinical compatibility, monitor-DPI or physical IME claim is made.

The bundled Slint 1.18.1 Fluent table forwards keyboard focus to an internal `FocusScope`, while its public `has-focus` property binds a separate scroll-view property. Therefore Cover Sheet table focus is not asserted through that property. The misleading Cover Sheet list-focus branches were removed from the test probe. Detail text focus remains a real widget probe; table return is checked with native arrows/selection. No delayed focus workaround or fake focus flag is used. Official [FocusScope documentation](https://docs.slint.dev/latest/docs/slint/reference/keyboard-input/focusscope/) distinguishes element focus from parent event delivery.

At the largest supported application scale (200%), the authored default window uses 1180x700 logical pixels; the ordinary 1180x800 default would extend below the reviewed 1440-pixel desktop. Other defaults remain 1180x800 and the minimum is 980x680. The compact default is a bounded policy for the reviewed setup, not a general monitor-fit or DPI-transition guarantee.
